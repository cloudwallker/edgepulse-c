# EdgePulse C

可移植的 C 设备内核与确定性故障模拟器。

**无需开发板、现成固件或虚拟机，即可编译运行嵌入式采集链路，验证通信协议、有界队列、配置恢复和看门狗重启。**

## 快速开始

需要 C11 编译器；测试另需 Python 3.9 以上，仅使用标准库。程序和核心模块全部使用 C，无第三方运行库依赖。

Windows 环境，GCC 已加入 PATH 时：

```powershell
./scripts/build.ps1 -Mode test
./build/edgepulse.exe --demo
```

若 GCC 或 Python 不在 PATH 中，给脚本传入 `-Compiler` 和 `-Python` 的可执行文件路径。支持 MSYS2 GCC，无需虚拟机。

Linux 环境：

```sh
make test
./build/edgepulse --demo
make sanitize
```

更换随机种子并输出 JSON：

```powershell
./build/edgepulse.exe --seed 42 --ticks 12000 --json
```

`--ticks` 范围为 10..1000000，每步推进 1 ms；`--seed` 范围为 1..4294967295。场景还会注入一次 5000 ms 停顿。非法参数返回 2，对账失败返回 1；`--help` 查看参数。

## 设计

| 模块 | 当前实现 |
| --- | --- |
| `src/protocol.c` | CRC16-CCITT-FALSE、小端序编码、82 字节流缓冲、半包粘包解析和逐字节重同步 |
| `src/store.c` | 两个 24 字节 RAM 槽、版本与 CRC 校验、最后字节提交、写入中断恢复及版本序号回绕 |
| `src/device.c` | 协作式采样、传感器与发送 HAL、16 帧 FIFO、队满拒绝新样本、重连重试和重启丢弃对账 |
| `src/main.c` | 固定种子传感器故障、通信断连、调度停顿、真实编码配置命令及遥测逐条核对 |

核心不使用动态内存分配。HAL 回调串行执行，要求及时返回；当前不提供线程或中断同步。每次 tick 最多采样一次、发送一帧，迟到的采样周期单独计数，避免集中补采。使用无符号毫秒差处理时钟回绕，相邻调用间隔必须小于 2^31 ms。

阈值控制输出为遥测中的告警标志，尚无真实执行器驱动。模拟看门狗在下一次 tick 检测到至少 5000 ms 调度间隔时重启：增加启动编号、记录队列清空数量、清除命令去重窗口并恢复配置。

### 通信协议

所有多字节字段采用小端序，最大负载 64 字节。

| 字节偏移 | 字段 |
| --- | --- |
| 0..1 | 同步头 `A5 5A` |
| 2..3 | 版本 `01`、消息类型 |
| 4..5 | 设备编号 uint16 |
| 6..9 | 启动编号 uint32 |
| 10..13 | 序号或命令编号 uint32 |
| 14..15 | 负载长度 uint16 |
| 16.. | 负载，末尾附 uint16 CRC |

CRC 覆盖版本字段至负载末尾，多项式 0x1021、初值 0xFFFF，不反射、不做末尾异或；`123456789` 的结果为 0x29B1。类型 1 遥测负载为 `时间戳:u32 + 毫摄氏度:i32 + 告警:u8`；类型 2 配置负载为 `采样周期:u32 + 阈值:i32`，要求设备编号及启动编号匹配。

解析器接受任意大小的传输片段。接收空闲或会话结束时，由调用者执行 `ep_parser_flush`，丢弃截断候选并恢复其后已完整的帧。解析器自身不管理时钟和空闲超时。CRC 用于检测误码，不提供命令身份认证。

### 配置与传输语义

- 采样周期为 10..60000 ms，阈值为 -40000..125000 毫摄氏度；默认值为 100 ms、30000 毫摄氏度。
- 配置先写入成功再生效。每个启动会话缓存最近 8 个成功命令编号；同编号同参数不重复写入，同编号异参数返回冲突。窗口淘汰或重启后不再保证该编号去重。
- 队列满时丢弃新样本并计数；发送失败保留队首等待重试。发送成功只表示模拟链路已接收，没有接收端 ACK、持久化遥测日志或恰好一次交付保证。
- RAM 配置槽可跨同一进程内的模拟重启保留；退出后重新启动程序会初始化为空。擦除原子性只是模型假设，真实 Flash 时序、磨损、部分擦除与掉电持久性仍需板端验证。
- 启动编号和计数器使用 uint32，会回绕；启动编号不跨进程持久化。需要全局唯一会话的场景应接入持久化启动编号或会话标识。

## 验证

```sh
python scripts/check_mutations.py --compiler gcc
```

标准测试入口运行 3 个 C 测试程序和 5 个 CLI 测试。协议测试逐条对账 10000 帧并处理 100000 字节异常流；存储测试覆盖 50 个中断位置；设备测试覆盖溢出、重试、传感器故障、看门狗、时钟回绕、重复与冲突命令及协议字段校验。独立缺陷植入测试检查 5 类错误，每类重复 3 次；编译失败或超时不算成功检出。

默认种子 20261023 产生 1159 个有效样本：交付 593、队满丢弃 550、重启清空 16、待发 0；另有 40 次传感器读取失败。这是刻意构造的严重断连恢复场景，不是零丢包吞吐测试。具体命令、结果与边界见[验收报告](docs/验收报告.md)。

GitHub Actions 配置了 Windows GCC 与 Linux GCC/ASan/UBSan 检查。本地验证情况记录在验收报告中，工作流文件存在不代表远端已经运行成功。

## 迁移到开发板

把传感器和发送回调替换为 ADC/I2C/SPI/UART 驱动，使用单调时钟调用 tick；将 UART/DMA 数据送入解析器，并按明确的空闲超时调用 flush。为 RAM 存储模型补充真实 Flash 后端，保持已验证的记录格式与提交顺序。随后在板端验证中断竞态、Flash 约束、真实看门狗、栈空间和电气故障。本项目尚不包含 MCU 启动文件、链接脚本、BSP、RTOS 或实板验收结果。
