# EdgePulse C 验收报告

验证日期：2026-10-25。对应 15 个项目包中的 P09「设备采集与控制系统」。本轮在 C 主机模拟版本上增加跨进程配置文件、排他锁和进程故障恢复，保留默认 RAM 演示及既有协议、缓冲和看门狗行为，不依赖已有固件、开发板或虚拟机。

## 交付内容

- C11 设备内核、协议解析器、双槽配置模型、可选文件提交后端及命令行模拟器。
- 传感器与通信 HAL，可替换为板端驱动；当前没有真实执行器，控制结果为阈值告警标志。
- `config set`、`config show` 与 `--store` 演示，支持 Windows 中文及空格路径。
- 3 个 C 测试程序、9 个 CLI 黑盒测试、14 个文件后端进程测试，以及 5 类缺陷植入验证工具。
- Windows PowerShell 与 Make 构建入口，Linux/Windows CI 配置，中英文 README 与真实持久配置命令输出图。

## 本机验证

Windows，GCC 13.2.0。主程序与测试使用 `-std=c11 -Wall -Wextra -Werror -Wpedantic`；默认构建另启用 `-O2 -g`。协议、存储与设备核心未使用动态内存分配，也不依赖操作系统。主机 CLI 与文件后端可为 Windows Unicode 转换分配内存。Python 负责黑盒测试、进程终止和缺陷植入，不参与设备运行逻辑。

```powershell
./scripts/build.ps1 -Mode test
./build/edgepulse.exe --demo
./build/edgepulse.exe config set build/device.epcfg 25 -12500
./build/edgepulse.exe config show build/device.epcfg
./build/edgepulse.exe --store build/device.epcfg --demo --json
./build/edgepulse.exe config show build/device.epcfg
python scripts/check_mutations.py --compiler gcc
```

可通过 `-Compiler`、`-Python` 或 `--compiler` 指定可执行文件位置。本轮 PowerShell `-Mode test` 退出码为 0，Windows MSYS2 环境下从空构建目录执行 Make 也通过全套适用测试。Linux 对应命令为 `make test`、`make sanitize`，可执行文件为 `./build/edgepulse`。本地未运行 Linux 或 ASan/UBSan；Windows MSYS2 下运行 Make 不等于 Linux 实机验证，远端结果以 PR 检查为准。

## 默认 RAM 故障场景兼容基线

不带 `--store`，参数为 seed=20261023、ticks=12000。一个调度步长为 1 ms，额外注入一次 5000 ms 停顿，总模拟时长 17000 ms；它不表示实际运行耗时。配置帧先将采样周期改为 10 ms、阈值设为 30000 毫摄氏度，并发送一次同编号同参数的重复命令。本轮实测与既有兼容基线一致，`persistent:false`、`accounting_ok:true`。

| 指标 | 数值 |
| --- | --- |
| 采样尝试 | 1199 |
| 有效采样 | 1159 |
| 传感器读取失败 | 40 |
| 成功发送与解析收到 | 593 |
| 队满丢弃 | 550 |
| 重启清空 | 16 |
| 待发帧 | 0 |
| 队列峰值 | 16 |
| 看门狗模拟重启 | 1 |
| 配置提交 / 重复命令 / 存储写入 | 1 / 1 / 1 |
| 遥测 CRC 拒绝 | 0 |
| 遥测字节校验摘要 | 3411655967 |

两个守恒式成立：1199 = 1159 + 40；1159 = 593 + 550 + 16 + 0。大量丢弃由故意设置的长期断连和 16 帧容量产生，展示有界过载策略与可观测性，不宣称零丢包。

## 跨进程配置与恢复

文件为两个 24 字节版本 1 记录，总长严格为 48 字节，沿用 generation、CRC 和末尾提交标记。已有文件至少须有一个有效槽；未知格式、短文件、空文件和双坏槽均拒绝打开，原字节保留。新文件采用独占创建，先初始化并同步有效默认配置（100 ms、30000 毫摄氏度）。初始化中断可能留下无效文件，后续打开会拒绝该文件，不自动覆盖。父目录不会自动创建，`.epcfg` 运行配置默认加入 Git 忽略规则。

`config set FILE PERIOD_MS THRESHOLD_MC` 先校验参数，才打开或创建文件并提交配置。`config show FILE` 不创建或写文件，输出 `period_ms`、`threshold_mc`、`generation` 和 `persistent:true`。`--store FILE --demo` 读取已有配置，持锁直至退出；为了保留协议与去重演示，它会重新提交同值配置一次并发送一次重复命令。因此演示前后配置值相同，generation 会增加一次。不同采样周期的持久化演示不能直接套用默认 RAM 指标。

本轮以四次独立进程调用完成如下实测，所有命令成功退出：

| 调用 | 采样周期 / 阈值 | generation / 结果 |
| --- | --- | --- |
| 新文件 `config set` | 25 ms / -12500 毫摄氏度 | 2，`persistent:true` |
| `config show` | 25 ms / -12500 毫摄氏度 | 2，文件字节保持不变 |
| `--store` 演示 | 25 ms / -12500 毫摄氏度 | `persistent:true`、`accounting_ok:true` |
| 演示后 `config show` | 25 ms / -12500 毫摄氏度 | 3，同值提交一次 |

持久化演示同样使用 seed=20261023、ticks=12000，总模拟时长 17000 ms。采样尝试 479，有效采样 463，传感器错误 16；发送及解析收到 246，队满丢弃 201，重启清空 16，待发 0。两项对账为 479 = 463 + 16、463 = 246 + 201 + 16 + 0。队列峰值 16，看门狗重启 1 次，配置提交/重复命令/写入尝试为 1/1/1，遥测 CRC 拒绝为 0，字节校验摘要为 2327817637。

打开会话全程排他：Windows 使用不共享的 `CreateFileW`，Linux 使用非阻塞 `flock`，并发 EdgePulse 会话立即失败；正常关闭或进程终止后释放锁。`show` 虽不修改配置，仍使用排他读写句柄，需要相应访问权限。仅支持本地普通文件，拒绝目录以及最终路径组件的符号链接或重解析点；后端不逐级遍历父目录来检查链接。

提交只触碰非活动槽，分三阶段执行：清除提交标记后同步；写第 0..22 字节后同步；最后写提交标记后同步。系统同步分别调用 Windows `FlushFileBuffers` 或 Linux `fsync`。后端成功确认后，RAM 镜像、设备配置和命令成功/去重状态才更新。文件后端拒绝 RAM 模型的部分写入参数。

写入或同步失败后，当前后端被标记为不可继续写，必须关闭重开。错误代表“结果未确认”，不能解释为“新配置必未生效”：最后一次同步失败时，磁盘可能已经包含完整新值。`store_writes` 是已接受的写入尝试数，失败尝试也计数。CLI 参数错误退出 2；I/O、锁、格式或对账错误退出 1，存储错误不输出成功 JSON，也不回显文件路径。

文件故障测试通过仅在测试 worker 中启用的 `EP_FILE_TESTING` 探针，在提交阶段握手后终止真实独立进程，再重开并核对旧或新完整配置。27 次终止覆盖清标记同步后、23 个负载字节写后、负载同步后、提交标记写后和最后同步后，均恢复完整配置。28 个写入/同步失败点均未返回应用成功，保持 RAM 配置和命令去重状态，并拒绝在失败会话中续写；短读写补齐测试也通过。生产构建没有这些测试探针。

## 缺陷植入方法

测试工具复制源码到临时目录，逐一注入 CRC 初值错误、丢弃计数缺失、命令去重失效、看门狗阈值失效和 NVM 擦错槽。每个变体必须先以严格参数编译成功，再由真实 C 测试以非零退出码检出。编译失败、运行超时和缺失编译器均作为测试环境错误，不冒充检出。每类错误重复运行 3 次，核对退出码及标准输出/错误一致。

这 5 类是明确选定的代表性缺陷，不等于遍历所有可能错误。通过代码字符串锚点定位变异位置，源码相应位置变化时，工具会明确失败，要求重新审核变异。

## 验收边界

本轮范围为 P09 的主机 C 核心、软件模拟与文件配置恢复，不视为 P09 全部硬件子包完成。不带 `--store` 时配置仅在 RAM 中跨模拟重启保留，进程退出后不保留；启用文件后端可跨进程恢复配置。文件测试面向明确提交边界的真实进程终止，不等于真实断电测试，也不承诺网络文件系统、块设备扇区独立性或首次创建文件目录项的掉电持久性。实际完成的验证以本报告结果表为准。

遥测仍无落盘。协议没有加密认证、接收端 ACK 或端到端恰好一次语义。命令去重窗口为当前启动内最近 8 个成功编号，启动编号也未跨进程持久化。

看门狗依靠下一次 tick 检测间隔，无法在同一线程永久卡死时自行恢复；这是模拟边界。HAL 需及时返回，当前无 RTOS 调度、线程安全或 ISR 安全保证。32 位计数和启动编号会回绕，重启进程重新使用初始启动编号。

本地未运行 Linux 或 ASan/UBSan；仓库配置相应 Linux 检查与 Windows CI，远端结果以 PR 检查为准，工作流定义本身不构成运行证据。未测板端采样精度、实时抖动、真实内存峰值、功耗或电气安全。后续有开发板时，可沿 HAL 和存储提交边界迁移，根据 Flash 擦除/编程约束适配，再开展至少 30 分钟实采、断线/拔设备/写配置掉电和栈水位验证。
