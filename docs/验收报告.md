# EdgePulse C 验收报告

验证日期：2026-10-23。对应 15 个项目包中的 P09「设备采集与控制系统」。本轮选择可在 Windows 直接运行的 C 主机模拟版本，重点覆盖协议、缓冲、配置恢复及自动化测试，不依赖已有固件、开发板或虚拟机。

## 交付内容

- C11 设备内核、协议解析器、双槽配置模型及完整命令行模拟器。
- 传感器与通信 HAL，可替换为板端驱动；当前没有真实执行器，控制结果为阈值告警标志。
- 3 个 C 测试程序、5 个 CLI 黑盒测试，以及 5 类缺陷植入验证工具。
- Windows PowerShell 与 Make 构建入口，Linux/Windows CI 配置，中英文 README 与真实运行指标图。

## 本机验证

Windows，GCC 13.2.0。主程序与测试使用 `-std=c11 -Wall -Wextra -Werror -Wpedantic`；默认构建另启用 `-O2 -g`。C 内核未使用动态内存分配。Python 只负责黑盒测试和缺陷植入，不参与设备运行逻辑。

```powershell
./scripts/build.ps1 -Mode test
./build/edgepulse.exe --demo
python scripts/check_mutations.py --compiler gcc
```

可通过 `-Compiler`、`-Python` 或 `--compiler` 指定可执行文件位置。Makefile 也已在当前 Windows 的 MSYS2 工具环境中从空构建目录完成编译和全套测试；这不是 Linux 实机运行结果。

| --- | --- |

## 默认故障场景

参数为 seed=20261023、ticks=12000。一个调度步长为 1 ms，额外注入一次 5000 ms 停顿，总模拟时长 17000 ms；它不表示实际运行耗时。配置帧先将采样周期改为 10 ms，并发送一次同编号同参数的重复命令。

| 指标 | 数值 |
| --- | --- |
| 采样尝试 | 1199 |
| 有效采样 | 1159 |
| 传感器读取失败 | 40 |
| 成功发送与解析收到 | 593 |
| 队满丢弃 | 550 |
| 重启清空 | 16 |
| 待发帧 | 0 |
| 队列峰值 | 16 |
| 看门狗模拟重启 | 1 |
| 配置提交 / 重复命令 / 存储写入 | 1 / 1 / 1 |
| 遥测 CRC 拒绝 | 0 |
| 遥测字节校验摘要 | 3411655967 |

两个守恒式成立：1199 = 1159 + 40；1159 = 593 + 550 + 16 + 0。大量丢弃由故意设置的长期断连和 16 帧容量产生，展示有界过载策略与可观测性，不宣称零丢包。

## 缺陷植入方法

测试工具复制源码到临时目录，逐一注入 CRC 初值错误、丢弃计数缺失、命令去重失效、看门狗阈值失效和 NVM 擦错槽。每个变体必须先以严格参数编译成功，再由真实 C 测试以非零退出码检出。编译失败、运行超时和缺失编译器均作为测试环境错误，不冒充检出。每类错误重复运行 3 次，核对退出码及标准输出/错误一致。

这 5 类是明确选定的代表性缺陷，不等于遍历所有可能错误。通过代码字符串锚点定位变异位置，源码相应位置变化时，工具会明确失败，要求重新审核变异。

## 验收边界

本轮完成 P09 的主机 C 核心和软件模拟测试部分，不视为 P09 全部硬件子包完成。配置仅在 RAM 中跨模拟重启保留，进程退出后不保留；遥测无落盘，也未进行随机杀进程持久化验收。协议没有加密认证、接收端 ACK 或端到端恰好一次语义。命令去重窗口为当前启动内最近 8 个成功编号。

看门狗依靠下一次 tick 检测间隔，无法在同一线程永久卡死时自行恢复；这是模拟边界。HAL 需及时返回，当前无 RTOS 调度、线程安全或 ISR 安全保证。32 位计数和启动编号会回绕，重启进程重新使用初始启动编号。

本机未运行 Linux ASan/UBSan；仓库配置了对应 CI，由 PR 检查结果单独证明远端是否通过。未测板端采样精度、实时抖动、真实内存峰值、功耗或电气安全。后续有开发板时，可沿 HAL 和存储边界迁移，再开展至少 30 分钟实采、断线/拔设备/写配置掉电和栈水位验证。
